# 认证：浏览器登记 + HTTP 自动重登

把认证切成两段：**设备登记 Enrollment** 走 ArkWeb 交互式登录（账号 + 密码 + 短信验证），同时把本机设备指纹登记为服务端"信任浏览器"；此后 **180 天信任期内**的每次冷启动用持久化凭据经**纯 HTTP + SM2** 自动重登，完全不启动 WebView。凭据存 asset（设备解锁后可读，无额外开关），**不持久化会话 cookie**；信任过期时被动降级回 Enrollment，不做过期提醒。

站点要求未被信任的设备必须过短信验证，因此首次登录无法绕开浏览器——这也是为什么一个原生应用里会存在 WebView 登录页。而站点自身的"信任浏览器"机制有效期 180 天且以设备指纹为键，因此信任期内可以纯 HTTP 重登：这就是必须把**我们生成的**设备指纹注入登录页与 `saveFinger` 请求的原因——服务端登记的必须是将来 HTTP 重登要出示的同一个值。

**Considered Options**：信任浏览器 cookie 路线（不存密码，靠 Web 引擎 cookie 跨启动持久化，冷启动用隐藏 WebView 静默重登后把 cookie 单向同步给 HTTP 栈）。它安全性更好，但要求每次冷启动都跑一次 WebView、依赖引擎 cookie 存储的持久性，且 180 天后同样退化为浏览器登录；而站点本就把"信任"绑定在设备指纹上，凭据路线恰好与之同构。

**Consequences**：设备上会存有账号密码，安全性由应用沙盒与 asset 加密承担。第 181 天起自动重登必然失败（服务端触发短信），必须显式降级到 Enrollment——参考实现只在响应为 `'[]'` 时才补救，漏掉了服务端直接拒绝这条路径。
