# 取证纪律

> 由 `AGENTS.md` 指向：**要截图、拉日志、写证据，或要下"这个现象存在/不存在"的结论时读这里。**

## 每条论断一个证据

- **两个论断不能复用同一份证据**：同一张 PNG 同时充当"刷新反馈"与"刷新后"的证据，等于两个论断都没有证据。
- **抓不到就如实写"未抓到"**：重复文件比缺失更糟，因为它看起来像有证据。
- **文件名里的状态词必须与画面内容一致**（实测，ticket 12）：曾有一张 `…-spring-final.png` 拍的实际是**秋季**画面。
  复用一张图支撑第二个论断前，先确认它拍的是那个状态；发现名不符实就**在文件名附近与文档两处**标注清楚，不要静默留用。
- **证据目录里只放交付证据**：拍错主题、拍成桌面之类的帧改名挪进该 ticket 的 `logs/`，不要留在 `evidence/`。

## 溯源

**取证必须可追溯到源码版本**：截图与日志记下当时的 `git rev-parse HEAD`；工作区脏时同时记 `git status --porcelain` 的哈希。
取证期间工作区被改动，该取证就不再对应任何提交，只能作为过程证据。

**更强的同一性判据是产物指纹**：报一个能被独立重算的东西（如解包 hap 后 `ets/modules.abc` 的 SHA256），
让对方能复核"这份证据对应的是不是当前代码"。`git status --porcelain` 的哈希含索引等元数据，不适合当唯一判据。

## 开关：自证要打在消费点

- **取证开关必须自证生效**：改掉开关值后，把**实际生效值**打进 hilog。
  曾有一次 `SLOW_MOCK_FOR_EVIDENCE=true` 的构建仍按 700ms 跑（疑似增量编译/常量内联未跟上）——
  只"以为开关生效了"，就会把"没抓到"误判成"现象不存在"。
- **"开关被设上了"不等于"它到达了每一条数据路径"**：
  `aa start --ps lohSemester=2025-2026-2` 在冷启动时立刻打出 `effective="2025-2026-2"`，
  但不去点课程 tab 的话，数据侧仍是站点当前学期。要证明开关起作用，必须看到**消费点**那一行（谁读它、谁用它）。
- **提交前用 `git show HEAD:FILE` 核对开关已复原**，不要相信自己"改回来了"。
  更强的做法：复原后重建并给出**产物级或视觉级**证据（见 `docs/agents/gates.md` 的"陈旧产物"）。

## 时间敏感的证据不要赌手速

单次 `devecocli ui` / `hdc` 调用要 15–35s，5 秒的窗口必然抓不到。
要抓瞬时状态就把延迟**直接改大**（一次用过 30000ms）并在取证后复原，而不是去赌一个更短的窗口。

## 先证明"我们发出去的东西"是完备的

在把失败归因给站点或架构之前，先把我们发出的请求/产物变成可观察量（请求头、cookie 名与长度、表单字段、实际写出的字节）。
实测（ticket 08）：冷启动纯 HTTP 重登一直失败于"响应里没有票据"，一度被升级成"要不要改 ADR-0004"的决策；
真因是 cookie 解析器读不懂平台给的格式 ⇒ 一个 cookie 都没入库 ⇒ POST 带着空会话发出。
**下游所有推断都会建立在错误的前提上**，所以这一步不能跳。

## 工具本身会撒谎

- **`devecocli log --keyword` 会丢 tag**（实测）：用 `--keyword 'data.notices'` 过滤时 `data.courses` 的行一条都不在
  ⇒ 差点把"课程表没取到"当成结论。要过滤就**先全量拉再本地筛**（或按时间窗），并先确认工具返回的是全集。
- **`read` 工具会截断超长行**：一个 34,992 字符的单行文件用 `read` 只回来 4,273 字符，据此搜关键词会得到**假阴性**。
  判据：读回来的字符数与文件大小/行数对不上，就先怀疑工具。检查 minified 文件或超长日志行时用 `Get-Content -Raw` + `.IndexOf()`。
- **hilog 单条有长度上限**（实测约 2400 字符会被截断）：要把完整响应体/大正文当证据，就**落到应用自己的存储再 `hdc file recv`**。
- **layout dump 只有 `type` / `bounds` / `children`，没有滚动偏移字段**；
  但因为 bounds 树覆盖列表项，两份 dump 逐字节相同**恰好是**"滚动位置未变"的正向证据——别读成"dump 看不出来所以不算证据"。
- **`ui click` 的坐标要用 layout dump 的 px**（按截图目测实测偏过 100+ px）；用法是位置参数 `ui click X Y`。
- **`ui screenshot` 不覆盖同名文件**（会报错）；截图目录必须已存在。这两条合起来容易留下**旧图当新证据**。

## 改设备上的东西之前

- **先 `aa force-stop`**：应用会把内存中的旧内容 flush 回去覆盖你的改动（实测 preferences 里的快照）。
- 改定长字段要**逐字节等长替换**（`dd … bs=1 seek=<偏移> count=1 conv=notrunc`），用文本读写会把文件头弄坏。

## 诊断补丁

**未提交的诊断补丁，唯一副本就是那个 patch 文件**——`git checkout --` 曾把当时唯一一份探针代码清掉。规矩：
① 探针代码先落成 `.dsh/logs/<ticket>-probe.patch`（`.dsh/` 已 gitignore，`git checkout` 波及不到）；
② 还原前再另存一份 `.keep`；③ **工作区脏的时候不要改 `AGENTS.md`**——曾被卷进补丁一起清掉。

## 证据放在哪

各 ticket 的证据放 `.scratch/<feature>/evidence/`，配套一份 `README.md` 逐文件论断表（**一个文件一条主论断**）。
过程文件（原始 hilog 拉取、layout dump、探针截图）放各自 `logs/`。

**图片/证据文件只留本地、不入版本库**（账号所有者裁定：本仓库只有一个开发者）。
哪些目录被忽略写在 `.scratch/.gitignore`；确需入库的**文字**证据用显式 `git add -f <具体文件>`，**不要整目录 force-add**。
