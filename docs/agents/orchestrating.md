# 统筹：派单、worktree 与串树处置

你派活而不亲自改代码时读这里：怎么决定并行、怎么开树配设备、派单里必须写什么、出了串树怎么收。

## 要不要开多 worktree

worktree 隔离**文件系统**（每棵树各自有 `entry/build`，构建产物不再互相覆盖），**不隔离设备与锁**——构建锁与设备锁仍各只有一把。

两种策略，也可以混用：

1. 每棵树配一台**独立设备**（推荐）。
2. 只开树、不给设备：设备留在你手上，线上排队等设备。

**实测**（两棵 `--detach` worktree 同时 `assembleHap --no-incremental`）：两棵各约 45s、都 BUILD SUCCESSFUL，各自起自己的 hvigor 守护进程、互不干扰。
⇒ **"构建成本翻倍"要收窄**：真正重复的只是 `ohpm install` 与缓存构建的一次性成本，**不是每次构建的墙钟时间**。

**并行粒度**：只在文件与层都**真正不重叠**时才开并行；同一个 feature 目录（`features/auth`、`domain/auth` 之类）下的两条线应当**串行**；多线并行时让**关键路径**上那条线先提交。

## 派单里必须写什么

- **树与设备必须是可执行的字面量绝对路径**——不许出现 `WT` / `BRANCH` / `DEV` / `TICKET` 之类占位符或空路径。
  2026-09-13 串树事故的根因就在这一侧：派单模板的占位符替换把整段路径吃掉了，agent 收到的原文里只有占位符，其中一名没停下询问、自己挑了一棵树，正好选到别人的树。发完让 agent 回贴一次 `git rev-parse --show-toplevel` 验证。
- **read/write/edit 的 `file_path` 一律用绝对路径**（前缀 = 那棵树的树根），`pwsh` 一律带 `workdir`——子 agent 的文件工具会把相对路径解析到会话工作区（= 主树，2026-09-15 实测）。
- 约定窗口回报：拿到窗口的 agent 收尾时明确回报**"窗口关闭"**。
- 把"**主树 `git status --porcelain` 为空**"当作**常规探针**用 ⇒ 生成器写进 `.scratch/` 的产物**必须被 gitignore**，否则探针常年误报。

## 串树了怎么处置

1. 把误置的**未提交改动字节级搬到它该在的树**（另存一份 patch 兜底）。
2. 把误置方的**证据与日志移到树外的隔离目录**——`D:\Koracan\source\harmony\learnOH-wt\_quarantine-*`，
   **它不在工作区根内，是工作区根的兄弟目录**；**不要直接删**。
3. 复原被污染的那棵树，并在**两个** ticket 里各写一句「变了什么、原证据作废到哪一步」。

## 收尾：删树前先停守护进程

1. `git worktree remove --force <path>`
2. **先杀掉那棵树的 hvigor 守护进程**，否则目录会因文件占用删不掉
   （现象 `failed to delete …: Permission denied` / `the file is being used by another process`）。
   定位：查 `node.exe` 进程的命令行里是否含那棵树的路径片段——**别按时间盲杀，那样会误杀主树的守护进程**。
