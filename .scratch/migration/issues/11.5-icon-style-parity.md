### Part B-2：**全应用底色**改纯白（账号所有者 2026-09-12 追加，纠正我原先"只改页头"的理解）

账号所有者的原话："背景不仅仅是页头，我用取色器测得**整个 APP 界面底色**都是 254,250,254"。

**我核到的根因（可直接用）**：

- 我们浅色主题的底色令牌在 `entry/src/main/ets/ui/theme/Tokens.ets` 的 `LIGHT_COLORS`：
  `background: '#FFFBFF'` / `surface: '#FFFBFF'` / `card: '#FFFBFF'`，
  另有 elevation `level1..5` = `#FAF0FB / #F7EAF9 / #F4E4F6 / #F3E1F5 / #F1DDF4`（品红偏色逐级加深）。
  你量到的 (254,250,254) 就是 `#FFFBFF` 经过截图色彩配置转换后的结果（每通道 −1）。
- **它来自参考实现**：参考 `src/App.tsx:220-222` 的 `background/surface = rgb(255,251,255)`、
  `:244` 的 `card = rgb(255,251,255)`、`:235-239` 的 elevation 五档 —— 我们是一比一抄过来的（Material 3 紫色种子的基线底色）。
  ⇒ **"底色改纯白"是对参考实现的有意偏离**，要按台账规矩新增/更新一条并写替代验收标准。

**要做的**：

1. **底色类令牌去偏色**（浅色）：`background` / `surface` / `card` → `#FFFFFF`；
   elevation `level1..5` → 中性（例如 `#FFFFFF` / `#FAFAFA` / `#F5F5F5` …），**不要**保留品红偏色。
2. **账号所有者已裁定：强调色不动、中性家族一起去紫调**（2026-09-12 追加确认）。三档写清楚，别只改一半：

     **elevation 要保持原来的明度阶梯**（level1..5 由浅到深），否则卡片/弹层的层次感会消失。
   - **一并去紫调（中性家族，同一原则）**：`onBackground`(`#1E1A1D`) / `onSurface`(`#1E1A1D`) / `surfaceVariant`(`#ECDFE8`) /

#### 2. 实现结构（一个闭集 + 一个渲染入口）

- `entry/src/main/ets/ui/icons/IconCatalog.ets`：`AppIcon`（**15 个成员的闭集**）+ `iconSpec()`（族/码位/回退短名）+ `iconGlyph()`（`String.fromCodePoint`，MCI 码位 >0xFFFF）。
- `entry/src/main/ets/ui/icons/IconFont.ets`：`registerIconFonts(manager)` —— **先确认 rawfile 在包里**（`getRawFdSync`）+ `registerFont` 不抛错；
  失败/成功都落 hilog；`getFontByName` 只作诊断（本模拟器对应用注册字体返回 `undefined`，**不能当判据**，见证据 §6）。
- `entry/src/main/ets/ui/icons/IconGlyph.ets`：唯一渲染入口；字体未就绪时渲染**可读文本**（有 `accessibilityText` 用它，否则用短名）。
  **注意** `@Prop` 名字不能叫 `size`（与 `CustomComponent.size(SizeOptions)` 冲突，编译期报
  `Property 'size' … is not assignable to the same property in base type 'CustomComponent'`）⇒ 用 `glyphSize`。
- 字体与许可证：`entry/src/main/resources/rawfile/fonts/`（见 §6 取样代价）。
- 注册点：`pages/Index.ets` 的 `aboutToAppear`（@Entry 根组件，早于任何子组件 build）。
