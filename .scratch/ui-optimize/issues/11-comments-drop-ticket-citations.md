## Comments

### 2026-09-13 · 统筹者派单前的范围界定（**这张 ticket 最后跑、且单独跑**）

**为什么必须最后**：其他每一张 ticket 都在往注释里写东西；它必须在一棵"别人都不再动代码"的树上做，否则刚清完又被写回来。

**规模（我先量过）**：`git grep -n -E "ticket|工单|验收条款|台账"` 在 `entry/src/main/ets/**` + `entry/src/test/**` 下命中 **约 547 行、约 140 个文件**。这是一次**判断密集**的清扫，不是纯删除 —— 计划好时间，别当成小活。

**清理范围（我给的界定，冲突时以本条为准）**：
- **要清掉**：`ticket NN`（含 `ticket 11.5` 这种小数形式）、`工单…第 N 条` / `验收第 N 条`、`spec 第 N 节`、台账编号，以及**没有编号但同样是文档指针**的说法（"本工单"、"工单要求"、"工单原文"、"工单交付节"）。
- **不要动**：① 指向**参考实现**的引用（`reference/learnOH-old/...:行号`）—— 那是本仓移植惯例，且参考实现是稳定工件；② **ADR 引用**（`ADR-0004` 这类）—— 架构决策是长期注册表，不是会过期的文档指针；③ 测试里**自述意图**的用法（"本文件逐条锁定该顺序"）。
- **技术句逐字保留**：注释里的解释必须留下来，只把指针去掉并让句子仍读得通。例：`工单验收第 3 条要求「失败有明确提示且不丢失已填内容」` → `失败要有明确提示且不丢失已填内容`。**不许**把句子削弱成"按需求实现"。
- **只剩指针的注释行整行删除**；注释块仍要配平。
- **范围限于代码注释**：`entry/src/main/ets/**`、`entry/src/test/**`，以及 `scripts/**` 的注释（改注释不影响生成物）。**`docs/**` 与 `.scratch/**` 不在范围内**（两份台账、验收记录、spec 里的编号本来就要留着）。

**我额外要求的自证**：
- **"只动注释"的机械证明**：交一个剥离脚本（或等价的检查）—— 把改动前后两侧的所有注释剥掉，剩下的代码必须**逐字节相同**。这比"我看了 diff"强得多，也是本次改动唯一可能悄悄改坏东西的地方。
- **grep 归零要连正则一起交**：把你最终用的那条正则贴出来，并给出归零的原始输出；再附一条**负对照**（拿一个已知存在的旧串去搜，必须还能命中），证明"归零"不是正则写错。
- 注释块配平检查、四个 node 脚本、`assembleHap --no-incremental`（**搜 `ERROR` / `ErrorCode` / `COMPILE RESULT`**）、以及单测真绿（先删 `entry/.test` + `--no-incremental`，核对 `test_result.txt` 的 `Times run:` 行与时间戳）。
