# 优化 / 缺陷修复：界面与交互收尾

Status: **ready-for-agent**

> 本 spec 覆盖账号所有者在真机上提出的界面问题、上一阶段登记的三条缺陷，以及移植期台账里记下的技术债。
> 术语用 CONTEXT.md 的词汇；与参考实现的关系见 docs/agents/porting.md（**参考实现只是标尺，不是完成定义**）。

## Problem Statement

账号所有者把应用装到真机日常使用后，遇到一批「小事」：页头显示的信息有的多余、有的根本不对（相对时间算一次就冻住），
有的图标变成了文字；横屏分栏时底栏横跨整个屏幕；公告里的图片显示成破图；作业已截止时点提交图标毫无反应也不说为什么；
打开过的公告未读蓝点不消失；设置里有一个拨了没有任何效果的开关。这些问题单独看都不大，但每一条都在日常使用里反复出现，
合起来让应用显得毛糙。此外，移植期为了与参考实现保持一致而刻意留下的几处限制，现在参考实现已降级为标尺，
其中若干条已经没有继续保留的理由。

## Solution

对上述每一条给出可观察的修复，并保证「当初为什么这么写」不再只存在于代码注释里（注释不再引用台账）。
修复以**「与参考实现一致」不再作为验收依据**为前提：凡是改动会偏离参考实现的，只记录理由，不再走「先复审再改代码」的流程。

分四类落地：

1. **页头 / 顶栏的信息与图标**：删掉文件页头多余的入口与裸计数；文件详情与课程详情的顶栏按钮从文字改为图标；页头相对时间不再冻结。
2. **横屏分栏版式**：底栏在分栏态下只占主栏（393vp）宽度。
3. **内容渲染与状态**：公告详情的内嵌图片能正常显示；提交入口在已截止时给出明确原因而不是静默；打开公告后未读蓝点立即消失。
4. **设置与遗留技术债**：移除没有效果的开关；清掉两处已登记的技术债。

## User Stories

1. 作为账号所有者，我希望文件页头不再出现「文件设置」入口，这样页头只保留真正有信息量的东西。
2. 作为账号所有者，我希望文件页头不再出现一个没有标签的裸数字，这样我不会对着一个不知道在数什么的数字发愣。
3. 作为账号所有者，我希望文件页头如果保留条数，它就必须带标签（例如「共 4 项」），这样它自己能说明白。
4. 作为账号所有者，我希望文件详情页顶栏的返回 / 刷新 / 分享是图标而不是文字，这样它和公告详情、作业详情的顶栏长得一样。
5. 作为账号所有者，我希望课程详情页顶栏的返回是图标，这样各详情页顶栏风格一致。
6. 作为账号所有者，我希望顶栏按钮换图标后仍能被无障碍朗读，这样读屏用户不会失去信息。
7. 作为账号所有者，我希望页头的相对时间在我切回这个页面时重新计算，这样我隔夜回来不会还看到「刚刚更新」。
8. 作为账号所有者，我希望相对时间的四个档位（刚刚 / N 分钟 / N 小时 / N 天）在重算后仍然正确。
9. 作为账号所有者，我希望横屏分栏时底栏只出现在左栏下方，这样右栏的详情不会被一条横跨整屏的底栏割断。
10. 作为账号所有者，我希望竖屏（单栏）时底栏仍然横跨整屏，这样单栏形态不受影响。
11. 作为账号所有者，我希望公告详情里的图片（例如课程微信群二维码）能正常显示，这样「扫码进群」这类信息不会失效。
12. 作为账号所有者，我希望相对路径的图片能解析到正确的站点地址，而不是一个不存在的合成路径。
13. 作为账号所有者，我希望作业已截止时点提交图标能告诉我「已截止、不能提交」，而不是什么都不做。
14. 作为账号所有者，我希望「不能提交」的原因不止一种时（已截止 / 未选附件 / 正在提交中），界面能分别说清楚。
15. 作为账号所有者，我希望提交拦截的行为不变（已截止就是不能提交），只是补上说明。
16. 作为账号所有者，我希望打开过的公告未读蓝点立刻消失，这样「未读」这个信号是可信的。
17. 作为账号所有者，我希望已读状态在重启后仍然保留，这样未读数不会自己涨回去。
18. 作为账号所有者，我希望已读状态与快照一起持久化，这样离线时也不会丢。
19. 作为账号所有者，我希望设置里没有「拨了没有任何效果」的开关，这样我不会以为它坏了。
20. 作为账号所有者，我希望设置页里留下的开关都是真的生效的（文件的两个设置、沉浸式设置）。
21. 作为账号所有者，我希望收藏同一条内容项两次不会产生重复的收藏 id。
22. 作为账号所有者，我希望在「屏蔽」视图里看到的收藏状态是正确的（已收藏的就显示已收藏）。
23. 作为账号所有者，我希望搜索能按文件的分类文本召回（前提是数据模型能取到分类）。
24. 作为账号所有者，我希望上述每一条修复都能被独立复核，而不只是「看起来好了」。
25. 作为账号所有者，我希望代码注释不再引用台账编号，这样注释不会因为文档过期而骗人。
26. 作为账号所有者，我希望我认领之外的问题（附件名搜索、拼音搜索、列表分页、公告详情显示课程名）这轮不要被动，这样改动范围可控。

## Implementation Decisions

**影响到的模块**（用职责描述，不写路径）

| 模块 | 这次要改的接口 / 行为 |
| --- | --- |
| 相对时间（纯函数 + i18n 键） | 档位计算逻辑不变；**新增一个「时间戳 → 展示文案」的入口**供页面每次显示时调用 |
| 页面生命周期 | 受影响页面在 **onPageShow** 时重新读取快照的抓取时间 |
| 公告详情链接重写（渲染层注入脚本） | 重写条件从「仅 http(s)」**扩展到「相对路径」**；需要一个**可注入的基础地址** |
| 公告详情 WebView 载体 | 基础地址改为**从响应 URL 推导**，而不是写死一个合成路径 |
| 公告快照持久化 | 持久化里**新增已读集合**；读回时与内容项合并 |
| 公告仓库的已读写入 | 打开详情时写入已读并触发界面刷新 |
| 提交判定（纯函数） | 截止状态判定**扩展为带原因**；提交按钮据此显示提示 |
| 图标闭集与渲染入口 | **扩 5 个图标**（刷新 / 分享 / 外跳 / 信息 / 预览）并补映射；渲染入口不变 |
| 文件详情顶栏、课程详情顶栏 | 文字按钮 → 图标按钮；保留无障碍文案与点击区域尺寸 |
| 底部 tab 栏与壳层 | 分栏态下底栏宽度收敛到主栏（393vp）；单栏态不变 |
| 文件页头 | 删掉「文件设置」入口与裸计数（ui_file_settings_open 键随之变为未引用） |
| 设置页 | 移除无效果的开关及其持久化字段 |
| 收藏 / 归档 / 屏蔽的标记迁移 | 置真**改为去重**；三视图口径**统一**（收藏不再是「全部」的子集） |
| 搜索字段表 | 若文件模型能取到分类，则补 category.title |
| 代码注释 | 删除剩余对台账编号的引用（含工单编号引用，若账号所有者要求二遍清理） |
| CONTEXT.md | 已新增**已读 / 未读**与**技术债**三条术语 |

**关键决策**

1. **参考实现只是标尺。** 本次改变一旦与参考实现不同，不再走「先写理由、复审、迁移编号」的流程；只在 docs/accepted-deviations.md **追加一条带日期的说明**（变了什么 / 为什么 / 原证据还成立到哪一步）。
2. **图标按钮保留无障碍文案。** 图标渲染入口已有一条「字体未就绪时渲染可读文本」的回退分支；改为图标时必须继续传可读 label，否则回退分支会退化成图标短名。
3. **文件页头的裸计数直接删**，不新造「展示判定」模块；ui_file_settings_open 键随之作废，需同步清理三份 string.json 与 i18n 键登记表。
4. **底栏宽度**：只在**分栏态**收敛到主栏宽度；判据复用现有分栏判定（断点 750vp + 横屏），**不新增断点**。
5. **破图的修法**：优先**从响应 URL 推导基础地址**（公告详情是带 query 的真实请求），而不是换一个写死的合成路径；相对路径的重写与现有 _csrf 重写**在同一段注入脚本里**，条件彼此独立。
6. **已读的持久化挂在快照上**：与内容项同一份持久化记录，读回时合并；不新开一份存储。
7. **提交入口**：拦截行为不变，只是**从「静默」变成「有说明」**；说明按原因分档。
8. **技术债 #30（收藏重复 id / 三视图口径）**：置真去重 + 口径统一。这会让若干现有单测的断言反转（它们当前钉的是「append 不去重」），**那些断言要一并更新**——这是有意的行为变更，不是回归。
9. **category.title**：只有确认文件模型能拿到分类时才做；取不到就**不做**，并在执行记录里写明原因。

## Testing Decisions

**什么算好测试**：只测**外部行为**，不测实现细节。纯函数（判定 / 解析 / 格式化）用单测钉住**输入 → 输出**；
界面用**设备侧截图 / layout dump 的 px** 作为验收；**不**为「某个组件内部调用了哪个函数」写断言。

**沿用已有的缝，尽量不新开**：

| 被测模块 | 既有先例（同类测试） |
| --- | --- |
| 图标闭集与映射 | IconCatalog 的单测 |
| 相对时间档位与文案 | UpdatedTime 的单测 |
| 公告详情注入脚本（含新的相对路径重写） | NoticeDetail 的单测（已用夹具断言脚本行为） |
| 公告快照持久化 + 已读合并 | NoticeRepository 的单测 |
| 提交判定（带原因） | AssignmentSubmission 的单测 |
| 收藏去重与三视图口径 | Favorites 的单测 |
| 设置持久化 | Settings 的单测 |
| 搜索字段表 | Search 的单测 |

**验收方式分级**（账号所有者 2026-09-13 定的口径）：

1. **可单测的** → 单测（上表）。
2. **界面类** → **layout dump 的 px + 同状态截图**：底栏命中区宽度（分栏态预期 = 主栏 786px、单栏态 = 全宽 2880px，平板密度 2）、顶栏按钮的 bounds、页头元素清单。
3. **真机** → 只在账号所有者能物理操作时做终验（本机模拟器**不能**旋转 / 缩放窗口）。
4. **门禁** → 四个 scripts/check-*.mjs 脚本 + assembleHap --no-incremental；判成败要**搜日志里的 ERROR / ErrorCode**，不能只看 BUILD SUCCESSFUL，也不能只看退出码。

## Further Notes

- **硬禁止（会毁掉不可恢复的东西）**：不真的提交作业（本账号 9 个学期 546 条作业全部已截止，提交不可撤回）；不在真机上点「退出登录」（真机凭据是短信登记出来的，免短信重登实测失败）；不改设备级永久设置（语言 / 分辨率 / 密度）。
- **已实测的现状基线**（MatePad Pro 13 / API 23 / 密度 2）：窗口 2880×1920px；两栏 = 主栏 786px（= 393vp）+ 分隔条 2px + 右栏 2092px；底栏 5 个命中区各 576px、**横跨整幅 2880px**。即**底栏整宽是当前事实**，其余分栏几何是对的。
- **未解现象**：账号所有者提供的三张真机截图里，左栏内容只画到约 x=460px、随后是一条约 360px 宽的空色带（#191919，该颜色不在配色令牌里），与实测的 786px 主栏**对不上**。这条**未归因**；实施时需要一次「同状态」的 layout dump 才能定性——**不要**在归因前改动分栏几何。
- **提交信息与注释里都不要写台账编号**：账号所有者 2026-09-13 裁定「文档会过期，代码不会」。这条规矩已写进 docs/agents/porting.md。
- **已完成的文档债清理**（本 spec 之前完成，不需要重做）：AGENTS.md、docs/agents/porting.md、docs/reference-quirks.md（含过时段落更正、编号冲突记录、文末新增「技术债」一节）；全部代码注释里的台账引用（54 个文件 / 95 处）已删除并验证（残留 grep 归零、注释块配平、四个脚本绿、assembleHap 产物刷新）。
- **可复核的判据都在代码里**：不要依赖本 spec 的行号或路径；用 grep 与单测自己复核。
